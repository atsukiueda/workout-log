# 筋トレ記録アプリ

部位タブから種目を選び、セットごとの重量・回数を記録して、その日・直近7日間の部位別の負荷を評価する Web アプリ（PWA）です。
ビルド不要の HTML / CSS / JavaScript だけで動きます。記録はブラウザ内に保存され、Supabase を設定するとログインしたユーザーごとにクラウドへ保存・同期されます。

## 起動方法

**`start.bat` をダブルクリック**すると、ローカルサーバーが起動してブラウザでアプリが開きます。黒いウィンドウを閉じるとサーバーが止まります。すでに起動中なら、ブラウザを開くだけです。ポート 8080 が使用中の場合は `start.bat 8081` のように番号を指定できます。

（`index.html` を直接開くと、ブラウザの制約で種目マスタ（CSV）を読み込めません。）コマンドで起動する場合:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File serve.ps1 -Port 8080
```

起動後、ブラウザで http://localhost:8080/ を開きます。

### スマホで使う場合

このフォルダを GitHub Pages などの HTTPS 静的ホスティングに置き、スマホのブラウザで開いて「ホーム画面に追加」してください。一度開けばオフラインでも動作します。
クラウド同期を設定すれば、ログインするだけでどの端末でも同じ記録を使えます（下記）。設定しない場合、記録は端末ごとに保存されるため、機種変更時は「設定 → 書き出し / 読み込み」で JSON を移してください。

## クラウド同期（Supabase）の設定

1. https://supabase.com でアカウントとプロジェクトを作成します（無料プランで足ります）。
2. ダッシュボードの **SQL Editor** で `supabase/schema.sql` の内容を貼り付けて実行します。テーブルと「自分の行しか読み書きできない」ルール（Row Level Security）が作られます。
3. **Authentication → Users → Add user** で自分のメールアドレスとパスワードのユーザーを作成します（「Auto Confirm User」にチェック）。
4. 自分以外が登録できないよう、**Authentication → Sign In / Providers** で「Allow new users to sign up」をオフにします。
5. **Project Settings → API** の Project URL と anon public キーを `js/supabase-config.js` に書きます。anon キーは公開前提のキーで、データは手順2のルールで保護されます（service_role キーは絶対に書かないでください）。
6. アプリの「設定 → クラウド同期」でログインします。この端末にある記録はアカウントに取り込まれます。

同期の動き:

- 入力のたびに約1.5秒後、変更のあった日だけを送信します。アプリを開いたとき・画面に戻ったとき・オンラインに戻ったときにクラウドの内容を取り込みます。
- オフライン中の入力は端末に残り、オンラインに戻ると送信されます（ヘッダーの ☁ に状態を表示）。
- 同じ日を2台で同時に編集した場合は、未送信の端末側の内容が優先されます。
- ログアウトするとその端末の記録は消えます（クラウドには残ります）。

## 画面

| 画面 | 内容 |
|---|---|
| 記録 | 「種目を追加」→ 部位タブ（胸・背中・肩・腕・脚・臀部・体幹・その他）から選択。セットごとに重量と回数を入力。前回の記録を表示し、入力欄の薄い数字にも前回値が出ます。回数を入れるとレストタイマーが自動で始まります（各種目の ⏱ ボタンでも開始） |
| 評価 | その日の総セット・総ボリューム、目標との比較（直近7日間の筋群別達成率レーダー＋筋群別の棒と目標範囲）、部位別の負荷（タップで筋肉別内訳）、種目ごとの評価（自己ベスト・前回比・回数目安・目的の推奨回数）、次のトレーニング（目標未達の筋群とおすすめ種目、部位ごとの回復状況） |
| 推移 | 部位ごとのボリューム（または換算セット）を日ごとの棒グラフで表示。期間は 14日／30日／90日。「全部位」は7部位を共通の縦軸で並べて比較、部位を選ぶと拡大表示。棒をタップでその日の内訳。下に筋群×週の目標達成率ヒートマップ（直近8週） |
| 履歴 | 記録した日の一覧。タップでその日の記録へ |
| 設定 | プロフィール（目的・トレーニング経験・身長・体重、BMI表示、目標に含める筋群）、データの書き出し／読み込み |

複数の動作ができるマシン（ペックフライ/リアデルト、アシストチン/ディップ、アダクター/アブダクターなど）は、記録時に「動作」を選ぶと対象筋が切り替わります。

## 負荷の計算方法

| 項目 | 計算式 |
|---|---|
| ボリューム | 重量 × 回数 の合計（Volume Load）。秒数で行う種目はセット数のみ |
| 部位への配分 | 主対象筋 100%、副対象筋は原則 50%（種目ごとの例外あり。下記）。日ごとの部位の値はその部位内で最大の配分を採用し二重計上しない |
| 目標との比較の単位 | 13の筋群（大胸筋・三角筋前部/中部/後部・上腕三頭筋・上腕二頭筋・広背筋・僧帽筋・腹筋・大臀筋・大腿四頭筋・ハムストリングス・ふくらはぎ）。週の目標セット数は筋肉単位の研究値のため。腹筋とふくらはぎは設定で対象外にできる。前腕・脊柱起立筋・内転筋群・中臀筋は目標の研究がほぼないため対象外 |
| 評価の目安 | 1回あたり部位ごと 3〜10 セット。7日間の目標は目的×経験で決定（下表） |
| 達成率 | 直近7日間の換算セット ÷ 目標下限（100% = 下限到達） |
| 回復の目安 | 通常48時間、1日に6セット以上行った部位は72時間 |
| レスト時間の初期値 | 目的×種目の種類。バルクアップ・ダイエット: 複数関節2分・単関節1分30秒、筋力アップ: 3分・2分、健康維持: 1分30秒・1分。筋肥大では60秒超でわずかに有利・90秒超では差がほぼない（Singer ら 2024）、経験者で3分休息が1分より筋力・筋肥大とも大きかった（Schoenfeld ら 2016）ことによる。設定で固定時間にも変更可 |
| 推定1RM | Epley 式：重量 × (1 + 回数 ÷ 30)。15回超のセットは対象外 |
| 自重種目 | 体重 × 係数 ＋ 追加重量（腕立て伏せ 0.64、懸垂 1.0、ディップス 0.95 など） |
| アシスト種目 | 体重 − アシスト重量 |

### 副対象筋の割合と根拠

種目ごとの値はマスタCSVの「副対象筋」に `筋肉名(係数)` で書いています（係数なし = 0.5）。

| 割合 | 対象 | 根拠 |
|---|---|---|
| 50% | 関節を動かして働く協働筋（プレスの上腕三頭筋・三角筋前部、ショルダープレスの三角筋中部、ロウ・プルダウンの上腕二頭筋、スクワット・ランジ・RDLの内転筋群など） | 67研究のメタ回帰で、間接セットを0.5と数える方法が最もデータに合った（Pelland ら, Sports Medicine 2025）。片手ロウの上腕二頭筋の成長はカールの約半分（Mannarino ら） |
| 25% | 主に姿勢保持・固定で働く筋（ロウの三角筋後部・脊柱起立筋、サイドレイズの僧帽筋、レッグカールの下腿三頭筋、スクワットの体幹など） | 筋電図での関与はあるが、肥大の直接的な根拠が乏しい |
| 0%（除外） | スクワット系・レッグプレス・ランジのハムストリングス、ヒップスラストのハムストリングス・中臀筋 | MRI研究でほぼ成長が見られなかった（Kubo ら 2019、Plotkin ら 2023）。一方スクワットでは内転筋群が大きく成長したため副対象筋に追加 |

### 目的ごとの週の目標（部位あたりの換算セット）

| 目的 | 中級者の目標 | 推奨回数 |
|---|---|---|
| バルクアップ（筋肥大） | 10〜20 | 6〜12回 |
| ダイエット（減量） | 8〜14 | 6〜15回 |
| 筋力アップ | 6〜12 | 1〜6回 |
| 健康維持 | 4〜8 | 8〜15回 |

経験による補正: 初心者 ×0.6、中級者 ×1.0、上級者 ×1.25。身長・体重は目標セット数には影響しません（体重は自重種目の負荷計算、身長は BMI 表示に使用）。

係数や目安の数値は `js/config.js` で変更できます。

## ファイル構成

```
index.html                 画面
css/style.css              スタイル（ライト／ダーク対応）
js/supabase-config.js      Supabase の接続情報（空ならブラウザ内のみに保存）
js/sync.js                 クラウド同期
js/timer.js                レストタイマー
supabase/schema.sql        Supabase のテーブル定義とアクセスルール
js/config.js               部位・筋肉の対応、係数、複数動作マシンの定義
js/calc.js                 負荷計算
js/app.js                  画面処理・保存
sw.js, manifest.webmanifest, icon.svg   PWA（オフライン・ホーム画面追加）
start.bat                  起動用バッチ（サーバー起動＋ブラウザ表示）
serve.ps1                  ローカル確認用サーバー
種目マスタ/トレーニング種目マスタ.csv   種目マスタ（アプリはこれを直接読み込む）
```

種目を追加・修正するときは CSV を編集してください。筋肉名は `・` 区切りで、`js/config.js` の `muscles` か `aliases` にある名前を使います（未対応の名前はブラウザのコンソールに警告が出ます）。
